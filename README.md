# dsh-memory

一个 **DeepSeek Harness** 插件：把「跨对话的记忆」做成一摞本地 Markdown + 一张索引表，再配上一套管理界面。
零依赖、无构建，纯手写 JavaScript（Host 半 + Client 半）。

> 模型平时的记忆成本只有系统提示词里的那一行大纲；只有压缩流水线（每 100 轮或点一次「仿生压缩」）才会调模型。

## 它做什么

- **一行大纲进系统提示词**：按分类分组的索引（`【教训】/【资料】/【说明书】/【项目记忆】/【其它】`），教训永远排第一，开头写清「什么场景下必须先读」；关键词是钩子，写的是「什么场景下必须点开这条」，不是摘要。
- **四个记忆工具**：`memory_read` / `memory_write` / `memory_update` / `memory_delete`，锁定项一律拒写；`项目记忆` 只走人工通道。
- **教训三段式**：写教训时强制填「场景 / 错误链条 / 绕开与修复」，并自动在大纲末尾追加一句「动手前先过一遍【教训】」。
- **设置页「记忆管理」**：搜索、分类折叠、新建/删除、待审批改稿的 diff 审阅、压缩状态。
- **记忆日志页**：会话顶部多一个「记忆」页签，仿轨迹列表 —— 操作分色标签、行内结果摘要、右侧详情（来源/类型/关键词/状态/时间/完整正文），来源可一跳跳回轨迹里那次工具调用。
- **回忆统计**：一轮 = 用户按一次回车；窗口内被读得少、且复核日超过当前淘汰窗口的条目会被标成待删除候选（条目越多，这条线越紧）；卡片上点「保留」即否决这次判定（只刷复核日，正文不动）。

## 快速安装

只能走 DSH 的 `plugin_manager`（官方唯一支持的安装路径）：

```jsonc
plugin_manager { "action": "install_bundle", "target": "<本仓库的绝对路径>" }
```

- **Host 改动（`index.js`）必须重启 DSH 生效**；
- **Client 改动（`client.js`）刷新页面即可**；
- 卸载：`plugin_manager { "action": "remove_bundle", "target": "@local/dsh-memory" }`。

## 已知边界

- 依赖宿主的私有槽位（`settings.section`、`conversation.view`、`commandUi.register` 等），**DSH 大版本升级后需要复核一次**。
- 设置页导航图标的字形由外壳按 section id 写死，本插件借用了 `archived-sessions` 这个 id 来拿到归档图标（否则会落回齿轮）。
- 记忆日志页是独立的 `conversation.view` 页签：外壳的轨迹行类型是固定枚举，第三方插件不能往里插新行类型。
- 数据全在本机 `~/.dsh/memory/`，不上传、不埋点；只有压缩流水线会把记忆正文发给当前配置的模型。

## 数据面

`~/.dsh/memory/`

- `MEMORY.md`：7 列索引表（文件｜关键词｜启用｜类型｜何时读｜复核｜受保护），**唯一索引**。
- `*.md`：一份记忆一个文件，YAML 头写 `name/description/type/reviewed`，下面是正文。
- `.tidy/status.json`：上次整理运行的记录，只有 `lastRun / result(ok|failed) / detail`。
- `.tidy/proposed/*.md`：待审批的改稿，**只存正文**；存在即代表有待审批方案。
- `.tidy/turns.json`：全局用户轮计数 `{count}`；`.tidy/recall.json`：回忆流水 `[{turn,file,ts}]`。
- `.tidy/compress.json`：压缩流水线状态 `{startedAt,finishedAt,stage,reason,files,detail}`。

**`status.json` 不存 `state` / `count`。** 待审批份数的唯一事实源是 `proposed/` 目录里有没有文件，由 `snapshot()` 现算；写进 `status.json` 就会在批准/忽略之后与事实不一致。读 `status.json` 时剥 BOM（PowerShell 5.1 写文件必带 BOM，`JSON.parse` 会直接抛错）。

**回忆率与「待删除」也是现算的**：不进索引表，索引只存人写的事实。**一轮 = 用户按一次回车**（`session/event` 的 `user/message` 且 `source.kind === 'user'`），工具调用、子代理、goal 自动续轮都不计数。窗口 = 最近 `min(100, 总轮数)` 个用户轮；分子 = 这些轮里**读过它的轮数**（一轮读多次算一次）；`pendingDelete` = 窗口内被读次数低于当前门槛 且 复核日距今超过当前淘汰窗口 且 启用 且 未锁定。2026-10-29 修掉一处错位：早先 `recordRecall` 把读记成 `turnCount + 1`（下一轮），当轮读的记忆要等用户再发一条才进窗口；现在记在当前轮，读完立刻计入。

**淘汰线随总量收紧（2026-11-15）**：记忆增长要像对数曲线——记得越多、删得越狠，但总量仍在缓慢上升。执行端是两条随条目数变的参数（`pruneDays(total)` / `pruneMinHits(total)`）：淘汰窗口 `45 → 10` 天，按 `45 / (1 + log2(total / 8))` 递减；「不算白记」的最低回忆次数 `1 → 5` 次，`1 + round(log2(total / 8))` 递增。8 条以内是最宽的一档（45 天 / 1 次），条目翻倍就收紧一档，`snapshot().prune` 把当前值透出给面板显示（`淘汰线 >17 天 / 回忆<3`），压缩分档（`stale`/`heavy`）用同一个窗口。条文永远由人拍板：收紧只是让「待删除」更容易出现，删不删仍然点按钮，`保留` 随时能否决。

**单条回忆率天然很低**（一条记忆在被需要的那一轮读一次就够，窗口 100 轮里读到 5 轮 = 5%），所以设置页顶部另给整体口径 `recallOverview()`：`anyTurns/anyRate`（窗口内多少轮真的想起过记忆）、`covered/total`（覆盖率）、`lessonTurns/lessonRate`（其中读【教训】的轮数，衡量预防性回忆有没有发生）。这三个数才用来判断机制好坏。

**面板顶部仪表**（`client.js`）：一整条单行网格（`gridTemplateColumns: 'auto repeat(4, minmax(84px, 1fr))'`），格子之间用 1px 竖线分隔，整排铺满可用宽度——不再有「数字靠右、左边一片空白」的两行排布。依次是：进度环（环 50px + `36/100 轮` / `距下次压缩` / `其中 N 轮有回忆` 三行）、`覆盖条数`（`covered/total` + 一条 `MiniBar` 比例条 + 脚注 `NN% 被读到过`）、`教训回忆率`（低于 20% 变警告色，比例条上带一条 **20% 刻度线**，脚注 `N 轮读过教训`）、`待删除`（>0 变警告色，脚注 `见卡片上小标` / `暂无`）、**六档口径量表**（六根柱由矮到高、当前档实心，模型看不到档位，人在这里看得出「总量把它推到哪一档了」）。数字 19px / 说明 11px，主次靠字号与条长，不靠加粗。

**分组标题**：折叠箭头 + 一颗 7px 分类色点（资料蓝 `#4c8bf5`、教训红 `#e2574c`、说明书绿 `#2fa36b`、项目记忆紫 `#8b5cf6`、其它灰 `#9aa0a6`、未分类 `#c4c7cc`，见 `CATEGORY_COLORS`）+ 分类名 + 数字胶囊 + 撑满剩余宽度的细线。

**进度环**（顶部仪表左边那个圆）：整圈就是一轮压缩周期（`compress.every` = 100 轮），两个量都以「轮」为单位直接叠在圈上——品牌色 40% 透明 = 距上次压缩已经走了多少轮（`compress.sinceTurns`），品牌色实心 = 这些轮里真有记忆被回忆到的轮数（`compress.recallSince`，从 `recall.json` 里按 `turn > 上次压缩轮` 去重数出来），轨道是主题的 `--dsw-alias-border-l2`（浅色/深色模式都跟着换）；实心段压在浅段上面、同一起点，所以「实心有多长」就是这一周期里召回的实际产出占比，圆心写它的百分比。`compress.lastTurns` / `sinceTurns` / `recallSince` 由宿主在 `snapshot()` 里算好；老状态文件没有 `turns` 字段时退回 `turns % every` 估一个周期起点，不会显示成空环。

**深色模式**：所有颜色都取主题变量（`--dsw-alias-*`），`client.js` 里不再有写死的环色与差异底色——早期版本用 `#e6e6e8` 环轨、`#ffc2c2` / `#b4efb4` 行底色，在深色主题下会刺眼，现改为 `--dsw-alias-border-l2` 与 `rgba(226,87,76,.28)` / `rgba(47,163,107,.28)` 叠色（深浅主题都读得清）。分类色点（`CATEGORY_COLORS`）是有意固定的辨识色，两种主题下都成立。`tools/selfcheck.mjs` 里有 `grep` 断言保证这几个写死色不再回潮。

**排序**（`client.js`）：工具栏分段控件切「回忆率 / 时间」，选中态换底色加粗，选择写进 `localStorage['dsh-memory.sort']`。回忆率 = 窗口内被读百分比降序（同分按更新时间），时间 = 卡片参数里的文件 `mtime`（精确到秒）降序；分类分组不变，只在组内排序。卡片上原来的「回忆率 N%」文字换成一条 42px 的细条 + 数字，长度比数字更快能比。

**批准只改正文**：`proposed/` 里只有正文，`approveFile()` 沿用原文件的 YAML 头（所以 description 不会被改稿冲掉），刷新复核日，删掉方案。

## Host 半边（`index.js`）

**系统提示词两段**
- `memory:outline`（order 9890）：按分类分组的多行索引，取自 `MEMORY.md`，停用条目不出现。开头两行是**场景钩子说明**（2026-11-13 改短）：关键词写的是「什么场景下必须点开这条」；动手改 / 删 / 装 / 跑命令之前先扫【教训】，提到旧事或接手旧任务扫对应分组，拿不准就查（查错一次调用，漏查要返工）。其后每行一组：`【教训】…`、`【资料】…`、`【说明书】…`、`【项目记忆】…`；组名已表明分类，关键词里省掉重复的前缀。教训组永远排第一。
  单条关键词超过 42 字时在 `/` 边界裁剪并加 `…`（预算扣掉分类前缀）；**不做整行截断**，任何一条记忆都不会从大纲里消失（旧的 240 字整行截断实测丢过 `huashu-motion-install`）。
  只要存在启用的教训，末尾追加一句前置检查：「【教训】的钩子写的是「会闯祸的场面」：命中就先 memory_read 读完，再动手。」
  静态成本约 2.1K token/请求（大纲三段 + 四个工具声明 = 3038 字，见 `PROMPTS.md`），不随记忆条数线性涨（单条关键词有裁剪上限）。
- `memory:tidy-status`（order 9900）：正常时零输出，异常才一行「待审批 N 份 / 上次失败：原因」。

**动手前提醒（2026-11-14 新增）**：光靠索引常驻不够——模型动手那一刻经常不回头看大纲。所以 `tools/post-execute` 里盯着本轮**第一次** `write / edit / pwsh / computer_use / memory_delete / memory_update`，在工具结果后面追加一段 text block：`【教训提醒】动手前扫一眼…：noahs-ark=删家目录/重装DSH · …`（`lessonHooksLine()`，最多 8 条）。同一轮只提醒一次（`lastRemindTurn`），该轮已经用 `memory_read` 读过任何教训就闭嘴（`lessonReadThisTurn()` 查 `recall.json` 当前轮）。这是**场景触发**：成本约 100 token/轮且只在真要动手时出现。

**破坏性命令硬闸门（2026-11-15）**：提醒之外再加一道硬限制。`tools/pre-execute` 里匹配 `Remove-Item / rmdir / rd /s / del /f / rm -r / git reset --hard / git clean -f / Stop-Process / taskkill / Format-Volume / reg delete / Unregister-ScheduledTask`（常量 `DANGER_CMD`），若这一轮还没读过任何教训，**直接 deny 一次**并把教训钩子写进拒绝理由，模型必须 `memory_read` 之后再原样重试。普通命令（`git status`、跑自检、读文件）不受影响。

**新建前查重闸门（2026-11-15，相似度由模型判断）**：模型爱开新条目，所以在 `memory_write` 上加一道**流程闸**而不是算分闸——相似度不交给代码算（字数窗口算出来的相似度既钝又会被措辞绕过），交给模型：先按索引里的名称和关键词判断，拿不准就用 `memory_read` 打开那几条读全文再判断。代码只做两件机械的事：

1. **必须交结论**：`dup_check` 写清「比了哪些、判成相似/相同/相关/无关、所以新建还是并入」，至少 10 字且含判定词（新建 / 并入 / 相似 / 相关 / 相同 / 无关 / 单开），否则拒。
2. **必须说真话**：结论里提到的任何条目名，都必须在这一轮真被 `memory_read` 读过（`readThisTurn()` 对 `recall.json`），否则拒——凭空报名字过不了。

所以闸门同时是回忆的硬流程：想单开就得先翻出可能重复的那几条。判成相似就改原文、相关就 `memory_update` + `append:true` 并进去、相同就别建。另有 `keywordTooVague()`：整条关键词都是 `插件/记忆/工具/说明/回忆` 这类空泛词直接拒。

**记忆总量管控（2026-11-18 新增，对模型黑箱）**：被控量是记忆条目总数，目标 `MEM_TARGET = 50`（10 条以下寥寥无几，100 条以上太多）。每个用户轮按 PID 算一个连续量 `u ∈ [-1,1]`：`err = (50 - 总数)/50`（正 = 太少），`u = Kp·err + ∫Ki·err·dt + Kd·d(err)/dt`，`Kp = 0.8`（小一点，避免一次波动就把口径甩档）、`Ki = 0.05`（积分限幅 ±0.6 抗饱和）、`Kd = 1.5`（大一点，合并/批量删这类骤变立刻反应）。同一轮内重复读快照只回上次的 `u`（面板每 3 秒轮询，不能让读一次就推进积分）。

`u` 映射成六套口径（`tierOf()`：`u=+1` → 第 1 套，`u=-1` → 第 6 套），每套只是一句话，模型看到的是正常提示，看不到「档位 / 计数 / PID」这些机制：

| 套 | 口径 | 淘汰窗口倍数 | 回忆门槛加码 |
|---|---|---|---|
| 1 | 记忆还少，新主题直接开一条 | ×1.5 | +0 |
| 2 | 新主题优先单开，沾边别合并 | ×1.25 | +0 |
| 3 | 先看现成的，能改旧条目就不开新 | ×1 | +0 |
| 4 | 优先改写：旧条目在讲这件事就改它 | ×0.85 | +1 |
| 5 | 少一条胜过多一条，沾边的并进去 | ×0.7 | +1 |
| 6 | 记忆已经很挤：一律改写或并入，能删就删 | ×0.6 | +2 |

当前套数写进 `.tidy/pid.json`，其那句话作为大纲第 3 行每轮下发；`pruneDays()` / `pruneMinHits()` 再按套数缩放（窗口夹在 7~60 天），所以「该记的时候记得住、该收的时候收得动」是同一套量在驱动。

**提示词检视（`/dsh-memory/prompts`）**：把模型在整个记忆流程里能看到的提示词原文一次交出来——大纲、四个工具声明（注册时由 `toolSink` 顺手抄录，不手抄、不漂移）、动手前提醒、两道拦截的拒绝理由、各校验器的报错原文、`/remember` 的隐藏指令。`PROMPTS.md` 是它的落地版：`$env:DUMP_PROMPTS="PROMPTS.md"; node tools/selfcheck.mjs` 重新生成。

**关键词口径（2026-11-13 再修订）**：关键词是**钩子**，不是摘要，也**不是句子**——写「**什么场景下必须点开这条**」，要具体、要勾人，像标题党一样让人在需要时非点不可；但要短：**每段 ≤10 字、1~4 段**（含分类），砍成名词 / 动词词组，别写「……前看」「……怎么用」这种尾巴。空泛词（`插件`、`记忆`、`工具`、`说明`、`回忆`）等于没写。
- 资料 → 认得出来的对象（`中文乱码/代码页/BOM`、`称呼/基本信息`）；
- 教训 → **会在哪个任务、哪一步闯祸**（`删家目录/重装DSH`、`会话注入/自拼消息`、`装完即验收`）；**不许写 400 / 422 / 报错 / 根因 / 修复** 这类事后症状——那些词在你真要犯错的那一刻不会出现在脑子里。`memory_write` / `memory_update` 会用 `LESSON_SYMPTOM_WORDS` 正则直接拒绝这类关键词，并用中文给出改写示例；
- 说明书 → **卡住时你正想干什么**（`MCP/懒加载/连不上`、`记忆读写/索引/大纲`）。

超限校验由 `keywordTooLong()` 执行（`KEYWORD_SEG_MAX = 10`、`KEYWORD_SEG_COUNT = 4`），`memory_write` / `memory_update` / 设置页双击改名三处都先验后写；旧的长句关键词不会被自动改写，改到哪条算哪条。

索引表允许手改，所以读取时会做分隔符归一：`;`、`·`、`,` 一律当 `/`（`normalizeKeywords()`），写坏的索引行不会让分类解析错位。

**教训正文三段式**（创建时强制）：① 场景（什么任务、什么动作会踩到，读者一看就知道「我现在就在这个场景里」）；② 错误链条（第一步做了什么、哪一步开始不对、为什么没察觉）；③ 绕开与修复（下次怎么走、已经部署了什么防护）。

**四个模型工具**：`memory_read`（名称 / 关键词 / 描述命中，返回正文；**可一次传多条** `file:"a、b"`，最多 6 条，缺的汇总在末尾不整单失败——降低「动手前扫一遍教训」的成本）、`memory_write`、`memory_update`、`memory_delete`。三个写操作对锁定的记忆一律拒绝。

**首关键词硬约束**：`memory_write` / `memory_update` 的第一个关键词必须是 `资料 / 教训 / 说明书 / 其它` 之一；`项目记忆` 只能由人工通道产生（设置页新建，或大脑按钮开出的 5 分钟窗口，只放行一次）。教训类另有**预防性校验** `lessonKeywordProblem()`：关键词里出现错误码（`400`/`422`/`5xx`）或 `报错 / 失败 / 根因 / 修复 / 崩溃 / 超时` 等事后症状词时直接拒写，并附正例。

**两道闸门**，都走同一个 `memoryKind()` 判定（`realpath` + `path.relative`，大小写 / `..` / 符号链接都归一到同一身份）：

| 路径身份 | `read` | `grep` / `glob` |
|---|---|---|
| `body` 记忆正文 | 拒绝，改用 `memory_read` | 拒绝 |
| `root` 仓库根 | 放行（read 目录本来就会失败） | 拒绝 |
| `index`（`MEMORY.md`） | 放行 | 放行 |
| `internal`（`.tidy/**`） | 放行 | 放行 |

`tools/post-execute` 对写进 `body` 的文件做 2000 字软提示：只提示，写入已生效；措辞刻意放轻，说重了模型会为缩字数丢信息。

**十七条路由**：`GET /dsh-memory/status`（兼 `?client=1` 心跳）、`GET /dsh-memory/calls`（按会话列记忆调用）、`GET /dsh-memory/prompts`（提示词检视）与 `POST keyword / open / approve-file / reject-file / toggle / protect / keep / create / delete / search / compress / remember / dockping`。

**记忆调用流水**：`tools/post-execute` 里记下每次 `memory_*` 调用（会话 id、轮、读/写/改/删、目标、关键词、字数，最多 400 条）到 `.tidy/calls.json`，供对话界面的「记忆」标签页显示；不进上下文、不写会话历史。

面板只在自身操作后更新，所以另有一条兜底：回到窗口（`window.focus`）自动重拉快照，工具栏也有「刷新」按钮；索引行在、文件不在的卡片标「文件已丢失」，垃圾桶改叫「确认清理」。

- `create`：人工通道，文件与索引行一起写；索引补不上就把刚建的文件撤回，不留孤儿。
- `delete`：锁定的拒绝；删文件 + 删索引行 + 顺带清掉指向它的未审方案。**文件已经不在磁盘上的死行也能删**（回包 `ghost: true`），否则卡片会永远钉在面板上（2026-10-28 实测：报「文件不存在」，再也清不掉）。
- `search`：关键词、「何时读」、frontmatter 描述、正文都算命中；正文命中回原文附近 ±2 行（最多 3 处）。
- `compress`：点「仿生压缩」（大脑图标 + 四字文案），立刻跑一次压缩判定（不阻塞，前端轮询 `status.compress.running`）。

**`/remember` 是客户端 action**（`ctx.commandUi.register`，大脑图标进斜杠列表），不产生 `command` 事件、不写会话历史：点一下只向 `POST /dsh-memory/remember` 发一个 `sessionId`：宿主优先借 DSH 的 **llm 服务**，把 `session.deriveMessages()` 出来的上下文原样当前缀、末尾追加一句隐藏指令（只存在于这一次请求里），**并把 `memory_write` 的工具声明一起递过去**——模型「往里填空」拿到的是协议层的 `tool-call-delta` 结构化参数，天然合法 JSON，不再出现「模型没有返回 JSON」。llm 服务不可用时退回插件自己发 HTTP + 只带转录 + 同一条工具声明（`tool_choice` 点名）。回 `{file, chars, turns}`。状态条挂在 `conversation.input.right`（输入框控件行）：「记忆中」→「记忆完毕，正文长 N」，下一次人类发言（`turns` 变大）后自动消失。

**不要**用 `agent.followup()` 往会话里塞提示词：它收的是完整 `UserMessage`，少 `id` / `role` 会把这条消息写进会话日志，DeepSeek 侧序列化出没有 `role` 的 `messages[i]`，整个会话从此每轮 422。

## 压缩流水线（每 100 轮 / 仿生压缩）

规则（2026-10-27 定稿）：

| 窗口内回忆次数 | 距今 < 2 周 | 距今 ≥ 2 周 |
|---|---|---|
| 0 次 | 中删减 | 报备删除（只标「待删除」，不花 token） |
| 1 次 | 轻调整 | 中删减 |
| 2–10 次 | 轻调整 | 轻调整 |
| ≥11 次 | 不送 | 不送 |

另有两类永远不送模型：锁定、已有待审改稿。触发点两个：全局轮计数每满 100 轮（`turnCount % 100 === 0`，只数人类消息），以及设置页「仿生压缩」按钮。

送模型的内容：一组「关键词 + 正文」+ 固定系统提示词（`model: deepseek-flash`、`thinking:{type:'disabled'}`），不带任何 DSH 工具提示。目标篇幅：轻调整 75%–90%、中删减 50%–70%（2026-10-28 用户定稿）；这些记忆写得很密，实测模型通常只能压到 95% 左右，所以比例是「尽量」不是门槛——只要比原文短 3% 就先给人看，没达标的在 detail 里标「未达目标比例」。压缩中途被关掉时 `compress.json` 只剩 `startedAt`，超过 15 分钟没 `finishedAt` 就在面板上显示「上次压缩中断」并把按钮变色。

**改稿走工具调用（2026-11-18）**：改稿不再是「让模型手写 JSON」，而是注册一个 `submit_rewrites` 工具、用 `tool_choice` 点名，参数 schema 里 `file` 用 **enum 锁死本批候选文件名**、`items[].{file,body}` 必填、`additionalProperties:false`。模型因此写不出不存在的文件、也不会把字段名写错；拿不到工具调用就原样重试一次，两次都拿不到才降级回 `response_format:{type:'json_object'}` 文本模式（`parseCompressItems()` 仍在，容围栏与前后废话）。

**输出预算按正文量算（2026-11-18）**：`max_tokens = clamp(本批正文字数 × 1.6 + 1024, 8192, 65536)`。改前固定 8192，实测一次 4 份的批次输出 7378 字紧贴上限，截断后 JSON 只剩半截，报成「模型输出里没有 JSON 对象」——`.tidy/compress.log` 里那几条「批次失败」正是这个原因。官方 max output 384K，这里只用了很小一部分。

**串行对话 + 前缀缓存（2026-10-28）**：同一档位的所有批次共用一条 `messages` 链（批次 → 助手改稿 → 下一批），DeepSeek 的自动前缀缓存因此一轮比一轮吃得多。实测同一组记忆：第 1 批 0%、重压那轮 65%、第 2 批 77%、重压 83%。每轮命中数/未命中数都写进 `.tidy/compress.log`。

**两个实测坑（2026-10-28，用户报「点了压缩没反应」）**：

1. `deepseek-flash` 默认就开思考，`thinking` 字段不传 ≠ 关闭，必须显式 `{type:'disabled'}`。
2. 思考 + `json_object` 一起上时，思考可能把整个输出预算吃光：回包 `finish=stop`、`completion_tokens` 全是 `reasoning_tokens`、`content` 为空，表现为「跑完了但什么都没有」。**用户 2026-10-28 定稿：压缩一律 `thinking:{type:'disabled'}`，不要再思考**；回包为空或被截断就原样重试一次；每条请求最多送 4 份（`COMPRESS_BATCH`），单批失败不拖垮整次压缩，失败原因进 `compress.json.detail`、面板红条与 `.tidy/compress.log`。

## Client 半边（`client.js`）

设置页「记忆管理」：

- 顶部工具栏：「新建记忆」（l2 轮廓）、搜索框（去抖 250 ms，命中后只留相关卡片并把原文片段贴回卡片）、「仿生压缩」按钮（大脑图标 + 四字文案，压缩中显示「压缩中」）、右上角提示条。
- 卡片按首关键词聚类成 `资料 / 教训 / 说明书 / 项目记忆 / 其它 / 未分类`，分类行可点折叠（只在界面上折叠，模型仍看到全部关键词）；搜索时自动展开全部组。
- 每张卡片：关键词双击改名、启用开关、锁定按钮、参数展开（含**创建/更新时间，精确到秒**）、打开位置、`回忆率 N%`、待删除标记旁的「保留」按钮（`POST /dsh-memory/keep`：只把复核日刷成今天，正文不动，一个淘汰窗口内不会再判待删除）、右侧垃圾桶两段式确认、审核（双栏 diff：删除行红底黑字、新增行绿底黑字，每栏顶部显示各自总字数；两版相同时禁用「批准」）。
- 顶部有「上次压缩中断」与「上次压缩失败」提示条；底部状态汇总与当前大纲原文。
- `/remember` 命令：对话里只出现一行「记忆中」，跑完变「已记住本对话」，外观由 `conversation.chat.commandview` 的 `remember` 行接管（大脑图标）。
- **「记忆」标签页**（`conversation.view`，id `memory-calls`，order 20）：与「对话」「轨迹」并列。左边是按会话的记忆日志，单行一条：操作标签（回忆/记忆/改写/删除/对话归纳，各自配色）+ 文件名 + 关键词；**时间不进行，只在详情里**。**时间正序**（老的在上、新的在下），首屏滚到最新一条，用户贴着底部时才跟随新记录。点一行在右侧开详情（仿轨迹检查器）：来源（工具/对话归纳）、类型、关键词、状态、时间、会话、字数、**完整正文**（回忆=真正注入模型的那段、记忆/改写=写进文件的正文、删除=删掉前的正文），带 `callId` 的还有「在轨迹中定位」按钮，直接跳到那次工具调用。列表接口只回轻量字段，正文走 `/dsh-memory/call?id=` 单取。正常但没数据时只显示居中的淡色「暂无记忆调用」，加载中什么都不显示；只有接口不可用（404 未重启 / 连不上）才在中间报错。DSH 的轨迹行是固定枚举（system/user/tool/…），第三方插件加不了新的行类，所以做成并列视图而不是轨迹里的一行。

样式只用官方 token（`--dsw-menu-surface-fill`、`--dsw-shadow-lv3`、`--dsw-radius-*` 等）；分类下拉是自绘的，不用原生 `<select>`。设置页图标借用外壳映射里唯一空闲的 `archived-sessions` id。

界面只放状态、数字、输入框、按钮，不加说明性备注。
